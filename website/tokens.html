Design Tokens

Sorleed components rely on a three-tier CSS token hierarchy generated from a single design contract. Every color, spacing, radius, and elevation token provides clean theming without overriding component internals.

Token Architecture

1. Primitive

Raw color values and scales (neutral, blue, green, amber, red, purple). Primitives are never consumed directly by components.

2. Semantic

Functional interface roles: --fc-color-surface-default, --fc-color-content-primary, and --fc-color-border-focus.

3. Component

Component-scoped properties such as --fc-balance-card-background and --fc-button-primary-bg.

Token Naming Rules

All token variables are prefixed with --fc- and use kebab-case:

tokens.css
/* Semantic definitions */
--fc-color-content-primary: #0F172A;
--fc-color-content-muted: #64748B;
--fc-color-border-default: #E2E8F0;
--fc-color-status-success: #10B981;

/* Component-level mapping */
--fc-balance-card-bg: #FFFFFF;
--fc-balance-card-border: var(--fc-color-border-default);
--fc-balance-card-text: var(--fc-color-content-primary);

Theme Customization

You can customize any brand color or typography variable at runtime by defining them on your root element:

global.css
:root {
  --fc-color-brand-primary: #635BFF;
  --fc-color-surface-default: #FFFFFF;
  --fc-radius-md: 8px;
}

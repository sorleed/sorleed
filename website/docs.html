Sorleed Overview

Production UI infrastructure engineered specifically for fintech, digital banking, wealth platforms, and double-entry accounting applications.

What is Sorleed?

Building modern financial interfaces is hard: sensitive numbers must be masked, currency conversions require strict rounding precision, and WCAG AA accessibility is legally mandated in regulated environments.

Sorleed gives engineering teams and autonomous AI agents complete UI ownership. We distribute source-first components built on pure CSS tokens with zero runtime lock-in. You can consume and build with Sorleed in three primary ways:

1

The Sorleed CLI

Recommended for Code Ownership

Copies standalone component source files, types, and CSS directly into your repository. You own the code: tweak it, audit it, and customize it without black-box package restrictions.

Terminal — Install CLI globally or run on-demand via npx 
# Option A: Run on-demand via npx (no global install required)
npx @sorleed/cli add balance-card

# Option B: Install the CLI globally
npm install -g @sorleed/cli
sorleed add account-summary
2

The React Package

61 Components Pre-Bundled

The complete library published as an npm package. Delivers all 61 pre-compiled components with full TypeScript definitions, tree-shaking support, and design token stylesheets.

Terminal & App.tsx — Install and consume 
npm install @sorleed/react

# Import in your application:
import { BalanceCard } from '@sorleed/react';
import '@sorleed/react/styles/tokens.css';
import '@sorleed/react/styles/balance-card.css';
3

How to Use Individual Components

Whether you distributed source files using the CLI or installed the complete package from npm, each component functions identically in your code. Here is how to add, style, and wire them into your financial workflows:

Step 1: Add or Import the Component

For CLI source code, run npx @sorleed/cli add <component-name> (for example: balance-card). If using the npm package, import directly:

Usage: Import Component & CSS 
// If installed via npm package:
import { BalanceCard, AccountSummary } from '@sorleed/react';
import '@sorleed/react/styles/tokens.css';
import '@sorleed/react/styles/balance-card.css';

// Or if added to your codebase via CLI:
import { BalanceCard } from './components/sorleed/balance-card';
import './styles/sorleed/tokens.css';
import './styles/sorleed/balance-card.css';

Step 2: Render in Your Interface

Pass props such as amounts, account numbers, and event handlers. All components accept standard React HTML attributes and ref forwarding:

Dashboard.tsx 
export function Dashboard() {
  return (
    <div style={{ display: 'grid', gap: '20px', maxWidth: '480px' }}>
      <BalanceCard
        title="Operating Treasury Checking"
        amount="$1,245,850.00"
        account="Account •••• 4829"
        allowToggleVisibility={true}
        onToggleVisibility={(isHidden) => console.log('Masked:', isHidden)}
      />
    </div>
  );
}

Supported Frameworks & Environments

Sorleed is designed with strict standard web technologies (semantic HTML5, native CSS variables, React 18 & 19). It runs out of the box across modern full-stack frameworks:

Next.js
Full React Server Components (RSC) and Client Component compatibility with zero SSR flash.
React (Vite)
Instant HMR support with zero bundler plugins required. Pure CSS custom properties.
Remix / RR v7
Streaming SSR and server loader friendly. CSS styles can be imported at route boundary level.

Static site generation (SSG) with islands architecture for marketing portals and dashboards.

Sorleed CLI

Copy canonical source directly into your codebase. You own the code: inspect it, edit it, customize it. The CLI is safe by design and never overwrites existing code.

Commands

Terminal
# Show command list and usage
npx @sorleed/cli --help

# List all available components and dependencies
npx @sorleed/cli list

# Output components in machine-readable JSON format
npx @sorleed/cli list --json

# Add an individual component to your workspace
npx @sorleed/cli add balance-card

# Preview file operations without writing anything to disk
npx @sorleed/cli add balance-card --dry-run

# Specify custom target output directory
npx @sorleed/cli add balance-card --dir ./src/ui

Files Added to Your Workspace

When running add <component>, the CLI distributes clean TypeScript JSX and CSS files directly into your project structure:

Workspace Tree
components/sorleed/<component>/index.tsx
components/sorleed/types/index.ts      (shared types)
styles/sorleed/<component>.css
styles/sorleed/tokens.css              (shared design tokens)

Import design tokens first, followed by your component styles:

App.tsx
import "./styles/sorleed/tokens.css";
import "./styles/sorleed/balance-card.css";
import { BalanceCard } from "./components/sorleed/balance-card";

Conflict Protection

  • Zero Overwriting: Any existing component file halts execution immediately before writing to disk.
  • Shared File Integrity: Shared files (such as tokens.css and types/index.ts) are reused only when byte-identical to the canonical source.
  • Safe Rollbacks: On any copy error, any newly created files during that specific invocation are automatically rolled back.
  • Predictable Planning: Run with --dry-run anytime to review planned modifications beforehand.

Design Tokens

Sorleed components rely on a three-tier CSS token hierarchy generated from a single design contract. Every color, spacing, radius, and elevation token provides clean theming without overriding component internals.

Token Architecture

1. Primitive

Raw color values and scales (neutral, blue, green, amber, red, purple). Primitives are never consumed directly by components.

2. Semantic

Functional interface roles: --fc-color-surface-default, --fc-color-content-primary, and --fc-color-border-focus.

3. Component

Component-scoped properties such as --fc-balance-card-background and --fc-button-primary-bg.

Token Naming Rules

All token variables are prefixed with --fc- and use kebab-case:

tokens.css
/* Semantic definitions */
--fc-color-content-primary: #0F172A;
--fc-color-content-muted: #64748B;
--fc-color-border-default: #E2E8F0;
--fc-color-status-success: #10B981;

/* Component-level mapping */
--fc-balance-card-bg: #FFFFFF;
--fc-balance-card-border: var(--fc-color-border-default);
--fc-balance-card-text: var(--fc-color-content-primary);

Theme Customization

You can customize any brand color or typography variable at runtime by defining them on your root element:

global.css
:root {
  --fc-color-brand-primary: #635BFF;
  --fc-color-surface-default: #FFFFFF;
  --fc-radius-md: 8px;
}

Accessibility (WCAG 2.1 AA)

Sorleed components are engineered to comply with WCAG 2.1 Level AA standards, with native semantic HTML, visible keyboard focus rings, programmatic ARIA attributes, and high contrast ratios.

Implemented Semantics

Requirement Implementation Details
Accessible Names Every input, button, and action control pairs with programmatic labels (aria-label or <label for>).
Error Association Error messages set aria-invalid="true" and are tied to controls via aria-describedby.
Focus Visibility High-contrast 2px focus ring with a 2px offset ensures unambiguous visibility for keyboard users.
Privacy Toggles Balance and credential privacy toggles use aria-pressed and state-specific descriptions.
Keyboard Navigation Full keyboard navigation via Tab, Space, Enter, and Arrow keys with zero keyboard traps.

Color Contrast Compliance

  • Body Text: Slate-900 (#0F172A) on white provides 15.8:1 contrast, exceeding the 4.5:1 AA standard.
  • Secondary & Muted: Slate-500 (#64748B) on white provides 4.8:1 contrast, passing AA minimums.
  • Focus Rings: Blurple (#635BFF) meets 3:1 non-text contrast against both white and neighboring borders.
